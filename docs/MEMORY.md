# Память проекта

Состояние на 2026-10-30. Секреты сюда не писать. Это рабочая память для следующих сессий.

## Продукт и главное требование

- AI-редизайн интерьера по фото: пользователь загружает комнату, выбирает стиль, получает визуализацию, затем может искать реальные товары по рендеру.
- Главная ценность: красивый новый дизайн при сохранении **пропорций, размеров и камеры помещения**.
- Кровать на том же месте, розетки, декор и встроенное **не обязаны** сохраняться. Пользователь хочет новый дизайн, а не перестановку старой мебели.
- При этом окна, двери и потолок нельзя произвольно добавлять/двигать: это тоже часть архитектуры. Этот пункт требует аккуратной формулировки в промте.

## Текущий пользовательский поток

1. Загрузка фото.
2. Выбор типа комнаты.
3. Кнопка **«Очистить комнату»** — опционально. Показывает пустую комнату; можно переключить «Оригинал / Очищенная».
4. Выбор стиля и параметров.
5. Генерация дизайна.
6. На готовом рендере — «Найти товары» за 1 кредит.

## Очистка комнаты

- Реализована кнопкой после загрузки: `POST /api/cleanup`.
- Очистка возвращает data URL; клиент показывает shell. Если выбрана «Очищенная», shell отправляется в `/api/rooms` как `cleanup_photo`.
- Сервер сохраняет shell в `rooms.precleaned_shell_path`; рендер использует его как source и не запускает очистку повторно.
- Шелл не хранится до запуска генерации. Отдельный кредит за очистку не списывается.
- Модель/промт очистки берутся из `cleanup.config.v1`, но флаг `cleanup.enabled` ручную кнопку не блокирует.
- Если очистка падает, показывается ошибка; молчаливого перехода на оригинал больше нет.
- Старый автоматический cleanup в `jobs.js` остался, но по умолчанию `cleanup.enabled=false`, поэтому без precleaned shell он не срабатывает.

## Промт и стиль

- `buildPrompt()` собирает: TASK → ARCHITECTURE LOCK → **ART DIRECTION (bespoke)** → SCALE → KEEP EXACTLY → FURNITURE MODE/PLACEMENT → RADIATOR/WINDOW/LIGHTING → STYLE BRIEF → STYLE REFERENCE → MATERIALS/COLORS → OUTPUT/AVOID.
- `ARCHITECTURE LOCK` запрещает новые окна/двери/ниши/балки/изменение пропорций; встроенное считается архитектурой.
- `styleDescription` берётся из `styles.prompt_description` и вставляется в `STYLE BRIEF`.
- Источник стиля переключается в админке → «Стили»:
  - `text` — только текстовый бриф, без фото-референса (текущий default);
  - `reference` — фото-референс, старое поведение;
  - `swatches` — material board с палитрой, без архитектуры.
- Активны 8 стилей (миграция `028`): **Скандинавский**, **Джапанди**, **Ваби-саби**, **Органик модерн**, **Тёплый минимализм**, **Биофильный**, **Современная классика**, **Средиземноморский модерн**. Остальные деактивированы; включаются в админке.
- У активных стилей заполнены подробные briefs; у scandi/japandi — по 6 свотчей. Swatch board генерируется `src/styleswatch.js`.
- **Арт-директор** (`src/artdirector.js`): vision читает реальное фото и пишет bespoke-направление (палитра, focal point, feature wall, материалы, свет, текстиль, декор). Вставляется в промт блоком `ART DIRECTION`. Отключается `ART_DIRECTION_ENABLED=0`; стоимость входит в `renders.cost_usd`.
- Пользовательские фото-референсы в режимах `text`/`swatches` игнорируются (`meta.user_style_ref_ignored`).
- Основная модель рендера: **FLUX 3 Image 1K** (`black-forest-labs/flux-3-image`, `app_settings`/`.env`; код-дефолт `src/modelconfig.js`). Vision: `google/gemini-3-flash-preview`.
- QA архитектуры **выключен** по умолчанию (`ARCHITECTURE_QA_ENABLED=0`). Не включать без прямой просьбы.

## Генерация и 429

- Image-вызовы сериализуются через `withImageSlot`, минимальный интервал `IMAGE_MIN_GAP_MS=10000`.
- При 429 до 4 попыток с паузами 10/20/40 секунд и учётом `Retry-After`.
- Баланс OpenRouter пополнен (актуальный остаток смотреть в кабинете OpenRouter). При повторных 429 снижать частоту.
- После ошибки рендера кредит возвращается автоматически.

## Подбор товаров

- 1 кредит за запуск на выбранный рендер; повторное открытие готового списка бесплатно.
- При ошибке или 0 проверенных товаров кредит возвращается.
- После нажатия «Найти товары»: detail vision → room templates → Yandex Search API → проверка карточек → visual score для hero → список без сметы.
- Админка → «Поиск»: включение, слои, регион, домены, пороги score, лимиты.
- По умолчанию включены только `hero` и `textile`; `finish`, `builtin`, `completeness` выключены, чтобы не искать крепёж, плинтус и случайные карточки.
- Яндекс Маркет отдаёт серверу SmartCaptcha, поэтому исключён из allowlist. Discovery идёт обычной выдачей, карточки проверяются в магазинах allowlist.
- Покрытие неполное: hero/свет/ковры/пол/часть текстиля находятся; стены/потолок/плинтус и часть магазинов дают fallback-ссылку.
- Дубликаты items исправлены: перед созданием позиций run очищается от старых items. Старый битый run и лишние кредиты возвращены.
- Смета, площади и количества не считаются. В таблицах есть nullable `quantity`, `unit`, `measurement_status`.

## Платежи

- Прод: Robokassa, `ROBOKASSA_TEST=false`, `PAYMENT_PROVIDER=robokassa`.
- Receipt включён: услуга «Доступ к онлайн-сервису генерации дизайна интерьера — пакет на N генераций», `tax=none`, `payment_object=service`.
- Возвраты (`REFUNDS_ENABLED`) выключены, ручной режим.
- ЮKassa оставлена как fallback.

## Открытые вопросы и риски

1. Модели всё ещё могут менять архитектуру, особенно при `reference` режиме. Text/swatches должны уменьшить утечку, но нужен live-тест.
2. Формулировка «сохранять только пропорции/размеры/камеру» конфликтует с проверкой окон/дверей/потолка. Нужно решить: окна/двери — часть lock или их можно менять.
3. QA выключен; не включать без просьбы.
4. OpenRouter 429 и низкий остаток кредитов.
5. Подбор товаров покрывает не все слои; finish/builtin/completeness по умолчанию выключены.
6. Старый демо-каталог не используется для новой сметы.
7. Cleanup-кнопка ещё не проверена живым пользователем end-to-end после деплоя.

## Правила для следующих сессий

- Не делать широких изменений промта, модели, cleanup, QA или стилей без прямой просьбы.
- Не коммитить и не деплоить без явной команды.
- Не менять активные стили и настройки поиска без подтверждения.
- Не сохранять секреты в репозиторий и в этот файл.
- Если требование противоречит текущему коду — сначала спросить, потом менять.
