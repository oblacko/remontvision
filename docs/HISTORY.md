## 2026-11-13 — консолидация вариативности в `src/variety.js`

- **Единый интерфейс.** Новый модуль `src/variety.js` сводит вариативность комнаты в одну точку входа `pickVariety(room, style, seed, used)` → `{ accent, axes, emphasis, avoid, ... }`: акцент только из палитры стиля (seed-ротация `accent → support → dark`), композиционный emphasis по seed, avoid-список из последних 5 рендеров комнаты. Поле `axes` зарезервировано для стилевых осей (следующая задача), пока пусто.
- **Поведение идентично.** `src/variability.js` остался реэкспортом с прежней сигнатурой `buildRoomVariability(options)` (для регрессии и старых тестов), `jobs.js` переведён на `pickVariety`. В `meta.variability` поле `accentHex` переименовано в `accent`; чтение истории направления читает оба (`accent` у новых, `accentHex` у старых рендеров).
- **Тесты.** `test/variety.test.js` — детерминизм по seed и поведенческая регрессия на фиксированных входах (золотые выходы прежней реализации + текст промта). Промт-регрессия 20/20 без изменения baseline.

## 2026-11-13 — две очереди рендеров: правки первыми

- **Очередь.** Миграция `063` добавляет `renders.queue` (`'base'`/`'edit'`, дефолт `'base'`) и частичный индекс `idx_renders_queue_claim (queue, created_at) WHERE status = 'queued'`. Enqueue проставляет очередь: базовые рендеры — `'base'`, правки — `'edit'`. `claimNextRender` теперь забирает сначала старейшую правку (`queue = 'edit'`), затем старейшую базу (`queue = 'base'`), сохраняя lease/`claimed_by`/fencing. Правка юзера больше не ждёт за чужим базовым рендером.

## 2026-11-13 — лёгкий опрос TaskDock (один поллер, без N+1)

- **Бэкенд.** `userGenerations` больше не делает два коррелированных субзапроса `credit_txn` на каждую строку (до 201 запроса на опрос): `credits_spent` считается одним агрегатным запросом `WHERE render_id = ANY($1) GROUP BY render_id` и джойнится в JS. В ответ добавлено поле `room_status` (статус комнаты), чтобы фронт видел живой прогресс генерации. Индекс не понадобился — `idx_credit_txn_render` (003), `idx_rooms_user` и `idx_renders_room` (001) уже обслуживают запрос.
- **Фронт.** Один поллер: `TaskDock` владеет опросом. Период 3 с, пока есть активные задачи моложе 60 с; 15 с — если активные старше; при отсутствии активных опрос выключен, данные обновляются при открытии дока и возврате фокуса на вкладку. `Room` (5 с) и `GenerationPanel` (2 с) больше не опрашивают сами — подписываются на общий контекст (`allTasks`/`room_status`) и один раз забирают полный результат комнаты по завершении. Прогресс, версии, флаги breakdown/roadmap, тост возврата кредита и черновик сохранены.

## 2026-11-13 — пайплайн: layout параллельно арт-директору, кэш-ключи по артефактам

- **Кэш по артефактам.** `room_analysis` (миграция `062`) хранит три независимых артефакта с отдельными ключами: facts/repair — `hash(photo, shell, style, styleDescription)`, layout — `hash(roomId, dimensions, keepFurniture, briefHash)`, art direction — `hash(photo, shell, style, concept, keepFurniture, dimensions, briefHash)`. `briefHash` — производный хэш функционального брифа комнаты (`briefForRoom`), без новой колонки. Смена стиля даёт хит layout и промах repair/art direction. Кэшируется только полный layout-план (`proposed` + предметы), неполный не замораживается.
- **Параллельность.** Layout стартует параллельно с арт-директором, когда пустота известна заранее (`keep_furniture=false`); при `keep_furniture=true` пустоту определяет арт-директор, и layout догоняет его последовательно (качество не ломаем). Контракт `buildLayoutPlan` принимает `{ photoPath, dimensions, brief, keepFurniture, usedStrategies }` — всегда по исходному фото, без стиля/концепта и без data URL арт-директора.
- **Измерения.** События `room_analysis_cache_hit`, `layout_plan_cache_hit`, `ms` в `art_direction_ok`/`design_direction_ok`/`layout_plan_ok` сохранены.

- **Очередь: аренда вместо blanket-requeue.** Миграция `051`: `renders.claimed_at`, `renders.lease_expires_at`, partial-индексы `(created_at) WHERE status='queued'` и `(lease_expires_at) WHERE status='processing'`. `claimNextRender` — `FOR UPDATE SKIP LOCKED` + lease 5 минут; воркер продлевает lease каждые 30 с; `requeueProcessing` и reaper трогают только истёкшие lease / queued старше 24 ч.
