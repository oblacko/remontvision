## 2026-11-05 — строитель и рецензент, промты в админке, удаление style reference

- **Проход A — строитель.** `buildArtDirection`/`buildRepairScope` получает original_photo и cleaned_shell (если очистка включена), возвращает `repair_scope`: пол, потолок, стены, двери, окна, хранение, направление. Арт-директор при очистке читает пустую комнату, а не оригинал.
- **Проход B — рецензент.** `reviewDesign` возвращает `changes` по слоям `floor, walls, ceiling, doors, windows, light, furniture, storage, textile`; декор, арт, ковры и микроперестановки отфильтровываются. Быстрые правки в UI берутся из `changes`; полный список — на шаге «Что можно изменить».
- **REPAIR SCOPE в промте.** При наличии `repair_scope` промт разрешает менять пол/потолок/двери/окна по действию, а не сохранять старую отделку. При `keep` элемент сохраняется; `null` — работы не выдумываются.
- **Промты в админке.** Новая вкладка «Архитектор»: версии designer/builder/reviewer/criteria, активация, сброс к дефолту. Активные версии сидятся и кэшируются; JSON-контракт валидируется в коде.
- **`repair_scope` в UI.** На шаге «Что можно изменить» отдельный блок «План ремонта»: пол/потолок/стены/двери/окна с действием и объяснением, плюс список хранения.
- **Статус рецензии.** `analysis.architect.status = ready|failed`; при сбое рендер сохраняется, UI не выдаёт пустоту за «всё хорошо». Если у старого рендера нет `changes`, UI строит подсказки из `layers`.
- **«Оставить мебель» удалено.** Остался один чекбокс «Очистить». `keep_furniture` вычисляется из него: очистка включена → пустая комната, выключена → сохраняем мебель. Арт-директор при очистке получает cleaned shell и инструкцию проектировать с нуля.
- **Старый procurement удалён из пользовательского пути.** Удалены `ProcurementPanel`, маршруты `/api/renders/:id/procurement` и `/api/procurement/:id`, воркер procurement. Старые `/buy/:id` и таблицы оставлены для истории.
- **Style reference удалён из воркера.** Пользовательская ветка `room.style_ref_path` убрана; админские референсы стилей работают. Колонка/старые файлы — отдельная миграция позже.
- **Мёртвые модули удалены:** `designoffers.js`, `catalogseed.js`, `/vision-agent` в catalog-service (рабочий агент — Node в app).
- Тесты: `npm test` 148/148; build OK. Живой тест: строитель вернул `repair_scope` (стены/потолок/двери/хранение), рецензент — 4 крупных изменения без микродекора.

Панель стала боковой (drawer), а не центрированной модалкой.

## 2026-11-03 — отдельная модель правок и несколько референсов за запрос

## Исправленные баги (важно помнить)

- **Двойная генерация**: воркер не менял статус queued при старте — два слота брали одну задачу, каждый рендер оплачивался дважды. Лечится атомарным `UPDATE ... RETURNING` в `claimNextRender`.
- Модель возвращала JPEG, сохранялся как `.png` — теперь расширение определяется по сигнатуре байтов (`detectImageExt`).
- `npm start` игнорировал `.env` (нет dotenv) — исправлено через `--env-file` (Node ≥ 20.6).
- `spendCredit`: `FOR UPDATE` с агрегатом невалиден в Postgres — блокируем строку `users`.
