Дата сборки: 2026-10-26. Статус: приложение работает локально и на VPS, автодеплой настроен.

## Инфраструктура

- **Репозиторий**: https://github.com/oblacko/remontvision (private), автор коммитов `Oblacko`.
- **VPS**: `root@77.222.38.7` (Ubuntu 24.04, Docker 29.9 + compose v5.6). Проект: `/root/remontvision`. Доступ по ключу `~/.ssh/rv_vps` (локально у разработчика и в секретах GitHub Actions), git pull — read-only deploy-key `rv_deploy`.
- **Автодеплой**: пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → SSH → `git pull` + `docker compose up -d --build` + `docker image prune -f`. Секреты репо: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`. `.env` на сервере деплоем не трогается.
- **Postgres 16** в compose (том `pgdata`), миграции из `migrations/*.sql` накатываются при старте app-контейнера (учёт в `_migrations`). Файлы (загрузки/рендеры/фото товаров) — в томе `appdata`, есть слой S3 (`src/storage.js`, reg.cloud `https://s3.regru.cloud`), включается переменными `S3_BUCKET/S3_ACCESS_KEY/S3_SECRET_KEY` в `.env`.
- **Важно про окружение**: переменная БД называется `RV_DATABASE_URL`, не `DATABASE_URL` — стандартное имя глобально экспортировано в `~/.bashrc` другим проектом (paperclip) и перебивает `--env-file`. На машине разработчика чужой `DATABASE_URL` указывает на Postgres проекта paperclip — никогда не использовать.
- **Прокси**: OpenRouter WAF блокирует диапазон IP хостера VPS (`403 Access denied by security policy`). На сервере в `.env` задан `HTTPS_PROXY=http://<user>:<pass>@95.164.203.249:9367` (тот же хост принимает и socks5). Код читает его в `src/openrouter.js` через undici ProxyAgent (undici v6 — v7 требует Node 22+).
- **Прод-доступ**: `https://www.remontvision.ru` — nginx (HTTP/2, gzip, HSTS, security-заголовки) проксирует на `127.0.0.1:3000`; TLS — Let's Encrypt, автопродление `certbot.timer` (дважды в сутки, dry-run проверен). `APP_URL` на сервере — `https://www.remontvision.ru`. Порт приложения наружу закрыт (`127.0.0.1:3000` в compose).
- **SEO**: title/description/keywords, canonical, Open Graph/Twitter, JSON-LD (`WebSite`, `Organization`, `WebApplication`, `FAQPage`), видимый блок «О сервисе» с FAQ, `robots.txt`, `sitemap.xml`, SVG-favicon.
- **Юридические страницы для ЮKassa**: `/prices`, `/offer`, `/delivery`, `/contacts`, `/privacy`; цены и описания услуг, цифровое получение заказа, оферта с AI-дисклеймерами и возвратами по закону, контакты и реквизиты самозанятого. Ссылки — в футере и окнах входа/оплаты.
- **Версии и акцепты**: `legal_docs` + `legal_acceptances` (пользователь, документ, редакция, время, IP, контекст регистрации/входа/оплаты). Текущая редакция — `2026-10-26.3`.
- **Кредиты и возвраты**: списание привязано к рендеру, при сбое/таймауте 24 часа кредит восстанавливается; история в `credit_txn`; API возвратов (`/api/admin/refunds*`) с расчётом неиспользованной части и ручным способом при недоступности ЮKassa.
- **Почта**: Resend API (домен `remontvision.ru`, шаблон Resend) с фолбэком на SMTP/dev-лог. **Файлы**: EXIF/GPS удаляются через sharp при загрузке. **Логи**: ротация Docker 10 МБ × 3.

## Функциональность (сделано)

- Рендер ремонта по фото через OpenRouter: основной `/images` с исходником в `input_references`, chat-фолбэк; максимум 2 внешних вызова, без retry-каскада и fallback-модели, с суммированием известных `usage.cost`.
- Валидация slug'ов моделей при старте (`assertConfig`) — падение до приёма трафика при неверном `RENDER_MODEL`; `input_references` отправляются только при поддержке модели.
- **Каталог и подборка**: товары отбираются до генерации (`src/curate.js`, бюджет × стиль), до 4 фото товаров — референсы; после рендера vision-разбор + матчинг по ключевым словам/цвету. Если vision пуст/упал — fallback на curated (первый рендер) или смету родителя (итерация).
- Aspect ratio рендера = реальные пропорции фото; `fitAspect` доводит выход модели до точной пропорции исходника.
- Полное логирование себестоимости: `cost_image_usd` + `cost_vision_usd` = `cost_usd` в json-логе и в `renders`; ошибки сохраняют известную стоимость.
- Аутентификация по e-mail (OTP 6 цифр, 10 мин, 5 попыток, атомарное списание попытки). Отправка через Resend (домен `remontvision.ru`, шаблон), фолбэк SMTP; в production dev-лог запрещён. Сессии httpOnly, 365 дней.
- Оплата ЮKassa: пакеты `2×99₽ / 5×229₽ / 15×599₽`, кредиты-ledger, атомарное списание, идемпотентный webhook, локальные `pack_id/credits` не перезаписываются remote-payload. Регистрация даёт 2 кредита. Любая генерация — 1 кредит; при сбое возвращается.
- Админка: каталог товаров; аккаунты с балансом, начислением/списанием кредитов, кредитным ledger и историей генераций.
- UI: вход/регистрация, баланс, история генераций с превью, честная «подборка товаров», ссылки «в магазин/поиск», пример до/после WebP. Покупка кредитов включена; возвраты отключены.
- **Редизайн**: новый React/Vite-лендинг на `/` и генератор-панель Kimi Agent: 10 стилей с превью, загрузка референса стиля, цветовая схема/акцент, бюджет, реальная генерация/правки через API, история версий, реальные товары и стоимость; RAL и разметка розеток — ориентировочные рекомендации. Старый полнофункциональный кабинет — `/app` (`?room=…`, `?buy=1`, история/админка). Сборка — `web/`, статика — `web/dist`; бюджет до 1000 тыс. ₽; SEO/OG нового лендинга.
- **Backend под новый генератор**: `rooms.palette/accent/style_ref_path` (миграция 007), style_ref уходит в `input_references`, схема/акцент влияют на промпт, 10+ стилей разрешены на `/api/rooms`.
- **Админка `/admin`** (React, стиль сайта): пользователи с балансом, корректировкой кредитов, историей генераций и ledger пополнений/списаний; пакеты кредитов (CRUD, активность, цены); стили (CRUD, обложка, prompt description, несколько референсов общего дизайна, привязка избранных товаров). Пакеты и стили теперь из БД (миграция 008); стиль-референсы и товары участвуют в генерации, `/api/packs` и панель стилей читают БД.
- Rate limit in-memory: 300 запросов/час/IP, `trust proxy=1`; OTP resend 10 с, 100 кодов/сутки; `support@`/`366079@` без OTP-cooldown.

## Исправленные баги (важно помнить)

- **Двойная генерация**: воркер не менял статус queued при старте — два слота брали одну задачу, каждый рендер оплачивался дважды. Лечится атомарным `UPDATE ... RETURNING` в `claimNextRender`.
- Модель возвращала JPEG, сохранялся как `.png` — теперь расширение определяется по сигнатуре байтов (`detectImageExt`).
- `npm start` игнорировал `.env` (нет dotenv) — исправлено через `--env-file` (Node ≥ 20.6).
- `spendCredit`: `FOR UPDATE` с агрегатом невалиден в Postgres — блокируем строку `users`.
