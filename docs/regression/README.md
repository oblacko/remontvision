# Регрессия промтов генерации

Фундамент для изменений рецепта генерации: 20 конфигураций — 5 комнат × 4 стиля. Никаких платных вызовов: скрипт собирает финальный текст `buildPrompt`, считает sha256 и сравнивает с baseline.

## Команды

```bash
npm run test:regression            # проверить текущий промт против baseline
npm run test:regression -- --update  # осознанно обновить baseline (коммит обязателен)
```

- `baseline.json` — зафиксированные 20 промтов (полный текст, hash, длина) и hash конфигурации правил админки.
- `last-run.json` — результат последнего запуска.
- `last-diff.txt` — появляется только при расхождении: baseline и текущий текст по кейсам.
- `changes/` — версионированные diff'ы, приложенные к изменениям промта (например, `2026-11-12-w2-2-geometry.diff`).

Код возврата: `0` — всё совпало, `1` — есть diff, `2` — baseline отсутствует.

## Матрица

| Комната | Габариты, м | Стили |
|---|---|---|
| Гостиная (зал) | 5.2 × 4.1 × 2.7 | Современный минимализм, Скандинавский, Джапанди, Лофт |
| Спальня | 3.6 × 4.2 × 2.7, кровать 2 м | те же 4 |
| Кухня | 3.1 × 4.6 × 2.7 | те же 4 |
| Санузел | 2.0 × 2.6 × 2.7 | те же 4 |
| Кабинет | 2.8 × 3.4 × 2.7 | те же 4 |

Параметры кейса: `priceTier=comfort`, `keepFurniture=true`, `useCatalog=false`, один source image, без style reference. Так промт остаётся детерминированным и не зависит от каталога.

## Правила

1. Любое изменение `buildPrompt`, `promptconfig.js` или room/style данных запускает `npm run test:regression`.
2. Diff прикладывается к коммиту/отчёту; `--update` — только после осознанной проверки diff.
3. `prompt_config_hash` в baseline ловит изменения правил из админки, даже если текст кейса не поменялся.
