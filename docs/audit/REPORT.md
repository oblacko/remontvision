# Аудит remontvision.ru

Дата: 2026-11-04. Объект: `https://www.remontvision.ru` (прод). Репозиторий: текущий проект (`app/`).
Аудит read-only: приложение не изменялось. Платежи, удаления, рассылки, изменения настроек, деплой, миграции, установка зависимостей, commit/push не выполнялись.
Для авторизованных сценариев создан **изолированный тестовый аккаунт** `audit-test-20261104@remontvision.test` (без реальных данных и без отправки писем).

## 1. Резюме

Визуально и структурно продукт сильный: редакционный лендинг, понятный оффер, аккуратный кабинет и админка, 0 консольных ошибок на всех проверенных загрузках. Главная задача (генерация по фото) **работает end-to-end**: 66 с, списание 1 кредита, результат + смета.

Ключевые проблемы — **рассогласование обещаний и фактического продукта**, а не дизайн:

1. **`/prices` показывает старые пакеты** (2/99, 5/229, 15/599) и ЮKassa, тогда как в БД/лендинге — новые (Комната 8/399, Квартира 15/599, Дом 50/1499) и Robokassa. Админка подтверждает: новые активны, старые выключены.
2. **Смета в генерации — из демо-каталога**, а не Hoff: позиции ведут на `/go/...` (поиск), реальных карточек/URL нет. Лендинг обещает «реальные товары и смету».
3. **Арт-директор на проде молча не отработал**: `cost_breakdown.art_direction = null`, в логах нет ни `art_direction_ok`, ни `art_direction_error`.
4. **Опубликованная статья без товаров**: 0 кнопок «Купить», 0 affiliate/erid.
5. **`/prices` ↔ лендинг ↔ генератор**: «бюджет» vs «класс материалов»; в генераторе каталог по умолчанию выключен.
6. **Небрендированные 404** (`Cannot GET`, голый текст «Статья не найдена»).
7. Мелкие: `max-age=0` у хешей, тяжёлые шрифты/бандл, `/app` в старом дизайне; sitemap статических страниц в порядке, нет только статей.

## 2. Метод и инструменты

- **Браузер:** headless Google Chrome 156 через CDP (`docs/audit/tools/*`), desktop 1440×900 и mobile 390×844.
- **Что собиралось:** рендер-DOM, скриншоты, консоль, сеть, `performance`-метрики, SEO-мета/JSON-LD, изображения/alt, кнопки/ссылки.
- **Клавиатура:** Tab-проход по лендингу (22 шага).
- **API/заголовки:** `curl` (`/api/health`, `/api/packs`, `robots.txt`, `sitemap.xml`, `Cache-Control`).
- **Авторизованный проход:** тестовый аккаунт + сессионная cookie; генерация 1 дизайна; read-only админка по `ADMIN_KEY` (вкладки без «Пользователи» и «Прокси»).
- **Lighthouse не запускался** — по правилам аудита нельзя ставить зависимости; вместо него лабораторные метрики CDP.

**Ограничения измерений:**
- Один профиль Chrome на серию → часть мобильных `transferSize` = 0 из-за кэша. Размеры — из desktop-замера и `web/dist`.
- Это **лабораторные** цифры с машины аудитора, не RUM.
- Скриншоты — только страницы без секретов/ПДн; тестовый аккаунт и статья публичные.

## 3. Факты и гипотезы

**Факты:** расхождение цен; смета из демо-каталога (`/go/`); `art_direction: null` без лога; статья без товаров; дефолт `use_catalog=false`; отсутствие бюджетного контрола в новом генераторе; небрендированные 404; `max-age=0` у хешей; 0 консольных ошибок; генерация 66 с и списание кредита; админка read-only грузится.

**Гипотезы:** влияние на конверсию/активацию; причина молчания арт-директора (вероятно, модель вернула пустой JSON — требует лога); эффект кэша/шрифтов/code-splitting на LCP. У каждой гипотезы — способ проверки в `BACKLOG.md`.
