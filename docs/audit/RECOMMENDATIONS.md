## 1. Продуктовая архитектура: один понятный путь

Сейчас в продукте смешаны старые и новые слои: старый `/app`, демо-каталог, Yandex-procurement, Search Lab, catalog-service/MCP, «бюджет» и «класс материалов», модальный поиск. Пользователь не понимает, что главное.

**Целевой канонический путь (только он в основном UI):**

1. Загрузить фото.
2. Комната: тип (обязательно), размеры (опционально).
3. Стиль (8 активных) или свой референс.
4. Опции: **класс материалов**; **каталог/товары — по умолчанию включён**.
5. Результат: рендер + авторский бриф + «Что видно на фото» + смета.
6. **Товары** — отдельный экран/панель (не попап), сохраняется.
7. Правка (текст/референс) — та же версия, история.

**Скрыть/убрать из пользовательского пути:**
- `/app` — редирект на новый генератор (или рестайл).
- поиск/лаб и MCP — только админка/служебный контур.
- демо-каталог — либо подключить Hoff, либо явно пометить «демо».
- «бюджет» — заменить на «класс материалов» везде.
- дубли систем поиска — один продуктовый путь: catalog-service (Hoff) + Yandex как fallback.

**Критерий:** новый пользователь без подсказок проходит путь «фото → дизайн → товары → правка» и понимает, где смета, а где реальные ссылки.

## 2. Поиск товаров: страница/панель с сохранением, а не попап

**Проблема (код):** `ProcurementPanel` — модалка; при закрытии `useEffect` делает `setRun(null)`, хотя run уже сохранён в `procurement_runs`. Повторное открытие не подхватывает результат. Пользователь теряет подборку.

**Решение:**
- Отдельный маршрут `/design/:roomId/products` (или боковая панель с URL-состоянием `?run=…`), а не модалка.
- На открытии: `GET /api/procurement/active?render_id=…` (добавить) или `GET /api/procurement/:runId` — восстановить последний `queued|processing|done` run.
- Хранить в URL `runId`, чтобы перезагрузка/назад/шаринг сохраняли результат.
- В кабинете — «Мои подборки» (список runs).
- Показывать **частичные результаты** и статусы по позициям; ошибка одной позиции не должна скрывать найденное.
- **Починить сеть:** импорт карточек использует SOCKS5-прокси (`127.0.0.1:10809`), которого нет на проде → `ConnectionRefused`. Для магазинов нужен **прямой dispatcher** (как в `payments.js` `DIRECT`) или рабочий HTTP-прокси; добавить health-check и fallback на direct, логировать причину, не ронять весь run.
- Кнопка «Повторить» для unresolved и честный `search_url` fallback.

**Критерий:** закрыл панель/перезагрузил — результат на месте; при падении прокси поиск идёт напрямую и показывает хотя бы частичные товары.

## 3. Лендинг: доверие, стили, примеры

**Чего нет (подтверждено скриншотами):**
- **Отзывов/соцдоказательств** (нет блока «Отзывы», кейсов, рейтинга).
- **Галереи стилей** (есть before/after 3 комнат, но нет 8 стилей с обложками/характеристиками).
- **Примеров по стилям и комнатам** как отдельной навигации.
- Явного объяснения, что такое «класс материалов» и что входит в смету.

**Добавить:**
1. **«Стили»** — 8 карточек (Скандинавский, Джапанди, Ваби-саби, Органик модерн, Тёплый минимализм, Биофильный, Современная классика, Средиземноморский модерн) с обложкой, 2–3 словами о палитре/материалах и ссылкой «примеры».
2. **«Отзывы»** — 3–6 реальных отзывов с фото/до-после, именем, датой; только настоящие, с модерацией; если отзывов нет — не выдумывать, а собирать после первых клиентов.
3. **«Примеры по комнатам»** — спальня/гостиная/кухня/санузел: before/after + что изменилось.
4. **«Что вы получите»** — рендер, палитра/RAL, список товаров со ссылками, правки.
5. **Гарантии** — 2 бесплатные, возврат кредита при сбое, без подписки.
6. **Честность** — если смета демо, писать «демо-подборка»; если реальная — «товары Hoff со ссылками».
7. **CTA-иерархия** — один главный «Загрузить фото», второй «Смотреть примеры»; на мобиле — липкая кнопка.

**Критерий:** посетитель за 10 секунд понимает: что получит, сколько стоит, где примеры и почему можно верить.

## 5. SEO и Wordstat (конкретный план)

**Wordstat API v2** (Yandex Cloud Search API, октябрь 2026):
- Endpoint: `https://searchapi.api.cloud.yandex.net/v2/wordstat/…`
- Методы: `topRequests` (топ и похожие за 30 дней), `dynamics` (по дням/неделям/месяцам), `regions` (гео), `getRegionsTree`.
- Авторизация: сервисный аккаунт Yandex Cloud, API-ключ scope `yc.search-api.execute`, `folderId`.
- Цена: ~20 ₽ / 1000 обращений `topRequests`/`dynamics`, ~50 ₽ / 1000 `regions`; квоты ~100/час и 10/сек.
- Старый `api.wordstat.yandex.net/v1` не использовать.

**Пайплайн исследования:**
1. Seed-список: `[комната] × [стиль] × [интент]` (дизайн, цвета, как собрать, товары, купить).
2. `topRequests` по региону 213 (Москва) и 2 (СПб), `numPhrases` 200–2000.
3. Кластеризация по интенту: информационные («как», «идеи», «цвета»), коммерческие («купить», «цена»), стилевые.
4. Маппинг: кластер → статья (title/H1/meta) → внутренние ссылки → CTA в генератор.
5. `dynamics` — сезонность (ремонт весна/осень), `regions` — приоритет гео.
6. Хранить семантику в БД (`seo_keywords`: phrase, count, region, intent, cluster, article_id) и обновлять раз в месяц.

**SEO-чеклист статьи:**
- Уникальные `title` (≤60) и `description` (≤160), H1 = тема, H2 по шагам.
- JSON-LD `Article` + `BreadcrumbList`; OG; canonical; `robots: index` для статей, `noindex` для тонких/дублей.
- Sitemap со статьями (генерировать при публикации).
- Внутренние ссылки: статья → генератор, статья → другая статья, статья → товары.
- Карточки товаров: `rel="sponsored nofollow"`, `erid`, честная цена/наличие.
- Изображения: alt, width/height, webp, lazy; обложка 3:2.
- Не публиковать «пустые» статьи без товаров/уникального текста.

**Кластеры контента:**
- «Дизайн [комната] в [стиль]» (8×12 = 96 потенциальных).
- «Цвета и палитра [стиль]».
- «Как собрать [стиль]» (мебель, свет, текстуры).
- «Товары для [стиль]» (lookbook с Hoff).
- «Ремонт [комната] бюджетно/премиум».

**Измерение:** позиции/CTR в Яндекс Вебмастере/Метрике (если есть), Wordstat-объёмы, переходы статья → генератор → оплата.
