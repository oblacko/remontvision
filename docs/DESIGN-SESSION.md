# Design Session: продуктовая и техническая модель

> **Historical document.** Актуальное состояние: [STATUS.md](STATUS.md).

Дата: 2026-11-04. Основано на разборе текущего пайплайна и обсуждении с владельцем.

## 1. Принцип

Один проект на комнату, а не мастер из модалок. Пользователь проходит путь:

`Комната → Дизайн → Разбор архитектора → Правки в том же чате → Готово`

Внутри — один экран: слева изображение, справа панель «Архитектор» с чатом и вкладками «Подсказки / Товары / Смета».

## 2. Шаги

### Шаг 1. Комната

- Фото.
- Тип комнаты.
- Стиль.
- Класс материалов.
- Чекбокс «Очистить комнату» — по умолчанию выключен.
- Чекбокс «Подобрать реальные товары» — по умолчанию включён, запоминается в сессии.

**Размеры комнаты не спрашиваем у пользователя.** Архитектор оценивает их по фото и сам передаёт в промт. Обязательно оценивается объектив: широкий угол растягивает ближний план и углы, поэтому метры корректируются с учётом дисторсии. Оценка и confidence сохраняются в `renders.meta`, чтобы было видно, откуда взялись размеры.

Очистка: состояния `off`, `running`, `done`, `failed_fallback_original`. Без отдельного кредита. Если не удалась — честно используем оригинал.

Товары: управляются в админке. «Товары в базовом кадре» — отдельный выключатель, по умолчанию выключен (A/B показал риск для архитектуры). «Подбирать товары после генерации» — отдельный, по умолчанию включён; на картинку не влияет.

### Шаг 2. Дизайн

Статусы: `queued → briefing → rendering → reviewing → products → done | error`.

Никаких фейковых процентов. Рендер показываем сразу, разбор и товары догружаем.

### Шаг 3. Разбор архитектора

Один vision-проход по сгенерированной картинке:

- комната, стиль, свет;
- стены/пол/потолок, материалы, палитра с hex;
- предметы с bbox, категорией, цветом, материалом, уверенностью;
- карта слоёв `walls / floor / furniture / light / ceiling / textile / decor / storage / appliances / art` с `impact`, `effort`, `risk`, `preserve` и точечными действиями;
- что получилось хорошо;
- 3–5 подсказок, привязанных к объектам;
- рекомендации по розеткам и свету;
- план товаров: категория, запрос, атрибуты.

Это заменяет `parseRender` + `matchCatalog` + `buildAnalysis` + `architecture QA` + `product_plan`.

### Шаг 4. Правки

Пользователь нажимает подсказку или пишет своё. Новая версия в той же сессии. После правки — дешёвый delta-разбор; полный — на «Готово».

### Шаг 5. Готово

Архитектор смотрит финальную картинку и даёт резюме:

- концепция и палитра;
- материалы;
- реальные товары Hoff с ценами и ссылками;
- чего нет в каталоге — честно;
- розетки и свет: где и на какой высоте;
- смета, если пользователь дал размеры;
- «что осталось купить»;
- экспорт PDF / шаринг.

## 3. Что убираем

- Architecture QA как отдельный платный проход.
- Демо-каталог `curateProducts` / `matchCatalog`.
- Yandex-скрапинг из пользовательского пути (только fallback для категорий, которых нет в Hoff).
- Абсолютный бюджет; остаётся класс материалов.
- Размеры комнаты в промте.
- Автобриф размеров по фото.
- Отдельную кнопку «Найти товары · 1 кредит» и модалку.
- «Товары в рендере» в базовом кадре.
- Дубли подсказок.

## 4. Данные по шагам

| Шаг | Собираем | Используем |
|---|---|---|
| Старт сессии | user_id, источник, устройство, referrer, эксперимент | воронка, сегменты, A/B |
| Фото | размер, mime, EXIF, резкость, экспозиция, тип комнаты + confidence, видимая область | предупреждение о качестве, промт, стиль |
| Оценка архитектора | габариты width/length/height + confidence, объектив: фокусное, wide/normal/tele, дисторсия, коррекция | промт, масштаб мебели, объяснение пользователю |
| Настройки | тип, стиль, класс, cleanup, products, референс, ширина кровати | промт, очистка, поиск, смета |
| Генерация | модель, версия промта, референсы, aspect, latency, cost, ретраи | unit-экономика, сравнение моделей |
| Разбор | комнаты, поверхности, hex, материалы, свет, предметы + bbox + confidence, issues, hints, electrical | подсказки, товары, финальное резюме, качество |
| Товары | item → query → offers (id, score, why, цена, наличие), покрытие | блок товаров, смета, ранжирование, клики |
| Правки | инструкция, target, референсы, parent version, latency, cost, QA | улучшение edit-промта, конверсия подсказок |
| Готово | финальная версия, резюме, стоимость, товары, розетки, экспорт | завершение воронки, NPS, кейсы |
| Обратная связь | подсказка полезна/нет, товар не похож, дорого, причина регенерации | ранжирование, промты, каталог |

Логи выбора товара (query → top-K → выбранный оффер → отклонённые) — датасет для будущего reranker.

## 5. Модель данных

- `design_sessions` — комната, стиль, класс, cleanup, products_enabled, статус.
- `design_versions` — версии рендера, parent, prompt, модель, стоимость.
- `design_messages` — чат: роль, текст, версия, действие.
- `design_analysis` — JSON архитектора по версии.
- `design_product_matches` — item → offer_id, score, why, статус.
- `design_events` — события воронки.

На Phase 1 переиспользуем `rooms`/`renders`, результат разбора кладём в `renders.analysis`.

## 6. Эффективность

- Один vision-вызов после рендера вместо четырёх.
- Каталог вместо скрапинга; Yandex только fallback.
- Кэш разбора по версии.
- Delta-разбор после правки, полный — на «Готово».
- Параллельно: разбор и поиск товаров.
- Один кредит за генерацию, включая разбор и первый подбор товаров.
- Стриминг состояний.
