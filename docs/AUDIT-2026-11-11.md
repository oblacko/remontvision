# Аудит и план оптимизации: 2026-11-11

Цель: довести основной путь «фото → стили → генерация → дизайн → редактор → разбор → паспорт → роадмап → товары» до состояния, пригодного для продаж.

Объект: репозиторий `app/`, прод-конфигурация не проверялась. Приложение локально не запускалось на момент написания раздела 2; замеры — этап 0.

## 1. Резюме

Продукт технически зрелый: очередь с lease и `claimed_by`, возврат кредитов, архитектурный QA, кэш direction, 363 unit-теста и 45 интеграционных. Преграды продажам:

1. **Долгое ожидание первого результата.** Картинка показывается только после vision-этапа `reviewDesign` («архитектор»), который идёт после генерации и блокирует `setRenderDone`.
2. **Варианты выглядят как правки.** В данных каждый вариант — отдельный `renders`-ряд, но кабинет группирует по комнате, а понятия «пакет генерации» нет.
3. **Пять вариантов идут по очереди.** Две сериализации: `imageChain` в процессе и глобальный Postgres-лок на всё время image-запроса.
4. **Перенос объекта непредсказуем.** Два разных предпросмотра, плоская вставка, скрытая цена правки.
5. **4K экономически опасен.** У FLUX 3 Image 4K стоит $0.607 против $0.048 за 1K.

Стратегия: быстрый показ, честные независимые варианты и прозрачная цена, затем польза после результата (разбор, паспорт, роадмап, товары). SEO-статьи — вторая стадия, в первой только поля данных.

## 3. Карта конвейера

`processRender` (`src/jobs.js`): брифинг арт-директора → direction (кэш 30 дней) → оценка размеров и layout → очистка (по умолчанию выкл.) → image → архитектурный QA → товарный QA (только для правки товаром) → `reviewDesign` («архитектор») → `buildAnalysis` → `setRenderDone`.

Общие для комнаты этапы: брифинг, размеры, layout. На стиль: direction. На вариант: image, QA, reviewDesign.

Сериализация: `withImageSlot` = `imageChain` + `getImageMinGapMs` + `withGlobalImageSlot` (advisory-lock `0x52564D31`). Повторы: только 429 (10–60 с) и таймаут; нет 402 in-flight, 502, 503, 403-модерации.

## 5. Принятые решения

| Область | Решение |
|---|---|
| Очистка комнаты | отдельного выбора нет; «сохранить мебель» всегда включено; «убрать мебель» — действие в редакторе |
| Быстрые кнопки 3/5 | новые; добирают до N разных стилей, не трогая выбранные; подобранные помечены и заменяемы; N = число отдельных дизайнов |
| Уровни | Старт / Про / Студия; модели и цены — в админке |
| Разрешения | 1K по умолчанию; 2K и 4K за доплату; только реально поддерживаемые моделью |
| Платные действия | цена на каждое действие в `app_settings`, по умолчанию 0; публичная ссылка паспорта/роадмапа бесплатна после покупки действия |
| Перенос | вариант A: починить текущий, замерить, затем решать про маску |
| Разбор | отдельная кнопка «Разобрать интерьер по предметам»; перенос и карта объектов доступны после разбора |
| Товары | ссылки на поиск магазинов + партнёрский Hoff; три типа результата; `rel="sponsored nofollow"` |
| Статьи | демо-дизайны и дизайны без пометки «приватно»; исходное фото не публикуется; явное уведомление при создании |
| Параллельность | лимиты в `app_settings`: система 8, пользователь 5, провайдер 4 |
| Эксплуатация | чеки — Robokassa; возвраты денег вне плана; диск увеличивает владелец; бэкапы отложены |

## 6. Модель данных

```sql
-- 054_generation_batches.sql
CREATE TABLE IF NOT EXISTS generation_batches (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  room_id TEXT NOT NULL REFERENCES rooms(id),
  tier TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'running', -- running|partial|done|failed
  idempotency_key TEXT UNIQUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
ALTER TABLE renders ADD COLUMN IF NOT EXISTS batch_id TEXT REFERENCES generation_batches(id);
ALTER TABLE renders ADD COLUMN IF NOT EXISTS reserved_credits INT;
ALTER TABLE renders ADD COLUMN IF NOT EXISTS cost_final_usd NUMERIC;
ALTER TABLE renders ADD COLUMN IF NOT EXISTS breakdown_stale BOOLEAN NOT NULL DEFAULT false;
ALTER TABLE renders ADD COLUMN IF NOT EXISTS publish_consent BOOLEAN NOT NULL DEFAULT true;
ALTER TABLE renders ADD COLUMN IF NOT EXISTS public_prompt TEXT;
```

Старые данные: пакет на группу рендеров комнаты одной даты; правки остаются на `parent_render_id`.

## 7. API

- `POST /api/rooms` + `Idempotency-Key` → `202 {batch_id}`.
- `GET /api/batches/:id` → варианты и статусы.
- `POST /api/renders/:id/retry` → новый вариант в том же пакете.
- `GET /api/quality-tiers` → уровни, цены, разрешения; без имён моделей.
- `POST /api/renders/:id/passport` → документ из разбора; `GET /api/renders/:id/passport.pdf`.

## 8. Этапы

1. **0.** Локальный запуск, тесты, базовые замеры, воспроизведение переноса.
2. **1.** Перенос объекта (P0).
3. **2.** Параллельность, обработка ошибок, идемпотентность, резерв/финализация.
4. **3.** Пакеты генерации, статусы, частичный успех, повтор.
5. **4.** Экран стилей: сетка, 3/5, уровни, разрешения, итог.
6. **5.** Кабинет: шапка, карточки пакетов.
7. **6.** Разбор по кнопке, новый промпт, устаревание.
8. **7.** Паспорт: экран и PDF.
9. **8.** Роадмап и поиск товаров по позиции.
10. **9.** Метрики, «Убрать мебель» в редакторе.
11. **10.** Сравнение дизайнов, «повторить в другом стиле», чеклист роадмапа.

Вторая стадия (отдельно): лендинг, админка уровней, SEO-статьи.

## 9. Тесты

Unit: `normalizeMove`, подбор стилей, цена уровня, статусы пакета, координаты. Интеграционные: идемпотентность, частичный успех, возврат, лимиты, lease. Нагрузочные: 1×5, 10×5, 50×1, сбой провайдера. Ручные: 390×844 и desktop, перезагрузка в процессе, двойной клик. Регрессия: существующие suite должны остаться зелёными.
