# Планы и запуск

**Статус на 2026-11-12:** сервис задеплоен после ночного прогона, очередь и тесты обновлены. Публичный запуск блокируют реальный каталог и эксплуатация.

## Где мы сейчас

- Генерация, мульти-стиль, правки, шаринг, разбор, роадмап, платежи, админка, статьи — работают.
- Очередь: lease/`claimed_by`/SKIP LOCKED, `WORKER_CONCURRENCY`, семафор image-вызовов.
- Direction слит с арт-директором, анализ комнаты кэшируется в `room_analysis`; регрессия промтов и CI-гейт перед деплоем.
- Очистка комнаты — асинхронно при первом enqueue, shell переиспользуется.
- **Каталог демо:** 100 товаров, 0 URL → заказов нет.
- **Смета новых рендеров пуста** (design-first); старый procurement не подключён.
- **Эксплуатация:** по проверке 2026-11-11 диск прода 91%, бэкап 45 ч без `db_dump`, внешнего монитора нет — требует перепроверки.

## P0 — до публичного запуска

1. **Реальный каталог**
   - 1 стиль × 1–3 комнаты;
   - 20–50 реальных товаров с URL, ценой, картинкой, габаритами;
   - импорт через админку или CPA/фид.
2. **Style kit из реальных товаров**
   - закрепить `style_products`, собрать комплект;
   - перегенерировать hero-референсы под реальный набор.
3. **Заказ**
   - `/go/:productId` + реальные URL; логи кликов;
   - позже — партнёрские ссылки/CPA.
4. **QA**
   - 10–20 реальных фото: спальня/гостиная/кухня/санузел;
   - геометрия, свет, декор, смета, ссылки;
   - canary-замер по [ops/QUEUE-CAPACITY.md](ops/QUEUE-CAPACITY.md).
5. **Эксплуатация**
   - бэкап: расписание, `db_dump`, off-site, алерты;
   - почистить диск (91%);
   - внешний uptime-монитор;
   - поддержка/возвраты/чеки; живой платёж.

## P1 — качество генерации

1. **Inpainting света/розеток** — маска/локальная правка вместо текста.
2. **A/B моделей** — Seedream / FLUX 3 / FLUX.2 Pro; слепая оценка.
3. **Upscale** 1K/2K → 4K.
4. **Direction** — замерить p50/cache hit после canary; при необходимости — батч на комнату.

## P2 — каталог и партнёры

1. **catalog-service:** visual_check (DINOv2 cosine + vision top-2), correction loop, `/vision-agent` UI.
2. **Покрытие:** 8–12 предметов, отделка, декор; reverse image search для unresolved.
3. **Партнёрские переходы:** CPA, subid, клики/заказы/выплаты.
4. **Обновление цен/наличия** из фидов.

## P3 — продукт/маркетинг

- SEO/лендинг, кейсы до/после, соцдоказательства.
- Публичные страницы стилей/комплектов.
- PDF-смета с фото и товарами.
- Аналитика воронки: фото → генерация → правка → клик → покупка.
- A/B тарифов/пакетов.

## Текущие ограничения

- Нет реальных URL → нет заказов.
- Смета новых рендеров пуста; legacy procurement не подключён.
- Inpainting отсутствует; один провайдер.
- Нет автообновления цен/наличия.
- Бэкапы/алерты не автоматизированы; диск 91%.
- Возвраты выключены, чеки вручную.

## Что нужно решить владельцу

1. Источник реального каталога: ручной импорт, фид, CPA.
2. 2 кредита за двухстадийку или 1.
3. Первые стили/комнаты.
4. Когда включать возвраты и автоматические чеки.
5. Судьба legacy procurement/Search Lab/статей (ядро или R&D).

## Definition of launch

- 20+ реальных товаров с URL в одном стиле/комнате.
- Смета ведёт на реальные карточки.
- 10 успешных canary-генераций; p50/очередь в норме.
- Платежи и возврат кредита при ошибке проверены.
- Бэкап БД и файлов сделан (с `db_dump`, off-site).
- Поддержка отвечает на письма.
- Маркетинговая главная готова.
