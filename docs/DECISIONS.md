# Решения (ADR-lite)

Короткие ответы на «почему так». Актуальный статус — [STATUS.md](STATUS.md).

## ADR-001: класс материала вместо суммы бюджета

Сумма в рублях не управляла подбором. Ввели `start|comfort|premium|atelier` на комнате и товаре. Сумма осталась справочно.

## ADR-002: design-first; смета — отдельный слой

Базовый кадр не получает product refs: исходник отвечает за геометрию, один art ref — за свет/палитру/материалы. **Следствие:** у новых базовых рендеров `render_items` пуст; смета заполняется у старых рендеров и при правках. Старое правило «curated-товары — источник сметы» больше не действует для новых генераций.

## ADR-012: сначала дизайн, затем товар

Hero-товар внедряется отдельной правкой с обязательным vision QA. QA сравнивает родителя, результат и карточку; ухудшение/недоступность проверки → `rejected` + refund.

## ADR-003: правила промта — в БД (с оговоркой)

Правила вынесены в `app_settings.prompt.rules.v1` и админку. **Оговорка:** `furnitureOff`, `catalogOn`, `styling` не доходят до генерации — известный баг (см. docs/redesign). Остальные правила применяются.

## ADR-004: свои hero-референсы, а не Pinterest-скрейпинг

Hero-сцены генерируются из наших товаров, проходят vision-скор и approve. Референсы по умолчанию не отправляются (режим `text`).

## ADR-005: очистка + дизайн при выключенной мебели

При `keep_furniture=false` и включённой очистке — два прохода: FLUX 3 Klein → shell → FLUX 3 Image. **Очистка выключена по умолчанию** (`cleanupconfig.js`); при включённой мебели — один проход. Биллинг — 1 кредит, хотя вызовов два.

## ADR-006: демо-каталог отделён от реального

100 демо-товаров — для проверки дизайна/стилей/UI. Реальные заказы невозможны, пока нет URL. Импорт по URL создаёт черновики. **На чистой установке сид каталога не запускается** (`catalogseed.js` удалён); в БД попадут только 10 товаров из миграции `001`.

## ADR-007: модель выбирается в админке

Render — `app_settings`/`RENDER_MODEL` (код-дефолт FLUX 3 Image); edit — отдельная (пусто = render); vision — `VISION_MODEL` (код-дефолт Gemini 3.1 Pro). FLUX 2 Pro не принимает `resolution`, возможна content moderation.

## ADR-008: прокси управляется из админки

OpenRouter WAF может блокировать IP VPS. Прокси в `app_settings`, применяется без рестарта, health-check, пароль маскируется.

## ADR-009: публичный шаринг без сметы

`/s/:token` показывает визуализацию, стиль, комнату, лайки, комментарии. Фото комнаты и смета не публикуются. Токен случайный, `noindex`.

## ADR-010: ссылки через `/go`

Ссылки из сметы идут через `/go/:productId?r=renderId` (лог клика + 302). MCP-поиск сейчас ведёт напрямую на `offer.url` и клики не логирует.

## ADR-011: габариты товара в промте

В базовом промте — только текстовые материалы/фоновые товары. Габариты hero-мебели — в product edit, чтобы карточки не управляли композицией.

## ADR-013: подбор товаров — MCP/catalog-service

Текущий путь: `POST /api/renders/:id/product-search` → visionagent + MCP + catalog-service. Бесплатно, один проход, до 20 предметов. Legacy Yandex procurement (1 кредит, allowlist, visual score) не подключён к API и подлежит удалению. Подробно: [PROCUREMENT.md](PROCUREMENT.md).

## ADR-014: очередь с lease и владельцем

`claimNextRender` — `FOR UPDATE SKIP LOCKED` + lease 5 минут + `claimed_by`. Завершение/heartbeat проверяют владельца; вторая реплика не крадёт in-flight задачу, а потерявший lease воркер не перезаписывает результат. Reaper: queued > 24 ч или processing > 60 мин. `WORKER_CONCURRENCY` управляет параллелизмом.

## ADR-015: direction кэшируется вариантами

Direction — текстовый вызов без фото; на паре «стиль × концепт» он повторяется у пользователей. Кэш `generation_cache`: 3 варианта, TTL 30 дней, выбор по `sessionId`, новизна — при выборе. Первый промах платит за варианты, дальше — мгновенно и без cost. Пустой `prompt_en` — негативный маркер на сутки.

## ADR-016: CI-гейт перед деплоем

Деплой зависит от job `test`: backend unit + integration (Postgres service), web lint/build, catalog pytest. Это ловит поломки, которые раньше уходили в прод.

## ADR-017: docs/STATUS.md — источник истины

Верхнеуровневые документы часто отставали от кода. Введён `docs/STATUS.md`: что сделано, что работает, что нет. Остальные документы описывают механику и ссылаются на него.
