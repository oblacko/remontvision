## Решение владельца 2026-11-21

- **Внешнее хранилище:** отложено. Копия остаётся только на VPS; G4 не подписывается,
  риск зафиксирован здесь.
- **Канал алертов:** Telegram. Нужны bot token и chat_id; в репозиторий не попадают.
- **Изменения прода:** запрещены в этой задаче («только отчёт»). Исполнение выносится
  отдельными задачами в `backlog`.
- **Окно для теста health:** не выдано; тест провести после настройки монитора.

## Что нужно от владельца / следующего исполнителя

1. **Telegram-бот** для алертов: token + chat_id (хранить у владельца, не в git).
2. **Аккаунт внешнего монитора** Better Stack/UptimeRobot (или разрешение на
   GitHub Actions fallback из [MONITORING.md](MONITORING.md)).
3. **Окно 10 минут** для теста G8: остановить `app`, получить алерт, поднять обратно.
4. **Внешнее хранилище** — когда владелец передумает: bucket/endpoint + ключ только на
   bucket, затем `rclone` + remote-копия по [BACKUP-RESTORE.md](BACKUP-RESTORE.md).
5. **`.env`**: положить актуальную копию в менеджер паролей/зашифрованный архив.

После этого: включить remote-копию, провести тест алерта, приложить `restore-verify`
отчёт и скрин алерта — тогда G4/G8 можно подписывать. Диск больше не блокер (39%).
